# Plan: MCP OAuth 2.1 Migration

## Context

The MCP server currently uses a custom 24-character API key (`mcp_tokens` table) for auth. The user wants to replace this with standard OAuth 2.1 (as defined by the MCP spec). This enables MCP clients (Claude Code, Cursor, VS Code, etc.) to handle auth automatically via their built-in OAuth flows instead of requiring users to copy-paste API keys.

Hard cut: no backward compatibility. API keys are removed.

---

## Architecture Overview

```
MCP client → GET / (401 + WWW-Authenticate)
           → GET mcp-server/.well-known/oauth-protected-resource
           → GET server/.well-known/oauth-authorization-server
           → GET server/oauth/authorize (user logs in via existing session)
           → POST server/oauth/token (exchange code + PKCE for JWT)
           → GET/POST /  (Authorization: Bearer <JWT>)
```

The **main server** (`server/`) becomes the OAuth 2.1 Authorization Server.  
The **MCP server** (`mcp-server/`) becomes a protected resource that validates JWTs locally.

## Step 1 — Database: New OAuth Tables + Drop Old

Create migration `server/src/db/migrations/021_oauth.sql`:

```sql
CREATE TABLE oauth_clients (
  client_id TEXT PRIMARY KEY,
  client_name TEXT,
  redirect_uris TEXT NOT NULL,  -- JSON array
  created_at INTEGER NOT NULL
);

CREATE TABLE oauth_auth_codes (
  code_hash TEXT PRIMARY KEY,
  client_id TEXT NOT NULL,
  user_id TEXT NOT NULL,
  scope TEXT NOT NULL DEFAULT 'mcp:tools',
  pkce_challenge TEXT NOT NULL,
  pkce_method TEXT NOT NULL DEFAULT 'S256',
  redirect_uri TEXT NOT NULL,
  created_at INTEGER NOT NULL,
  expires_at INTEGER NOT NULL,
  used_at INTEGER
);

CREATE TABLE oauth_refresh_tokens (
  token_hash TEXT PRIMARY KEY,
  client_id TEXT NOT NULL,
  user_id TEXT NOT NULL,
  scope TEXT NOT NULL DEFAULT 'mcp:tools',
  created_at INTEGER NOT NULL,
  expires_at INTEGER NOT NULL,
  revoked_at INTEGER
);

DROP TABLE IF EXISTS mcp_tokens;
```

## Step 2 — Main Server: OAuth Authorization Server

### New env vars (`server/.env`):
- `JWT_SECRET` — min 32 chars, used for HS256 JWT signing (shared with MCP server)
- `MCP_SERVER_URL` — e.g. `https://mcp.elementarmory.com` (for audience claim)

### New service: `server/src/services/oauth.ts`

Functions:
- `registerClient(name, redirectUris)` → stores in `oauth_clients`, returns `client_id`
- `createAuthCode(clientId, userId, scope, pkceChallenge, redirectUri)` → 32-char nanoid, stored hashed, 5-min expiry
- `exchangeAuthCode(code, clientId, codeVerifier, redirectUri)` → validates PKCE, issues JWT + refresh token
- `refreshAccessToken(refreshToken, clientId)` → validates, issues new JWT
- `issueJwt(userId, planCode, scope)` → HS256 JWT, 1-hour expiry, claims: `{ sub, iss, aud, exp, iat, scope, plan }`
- `validateJwt(token)` → returns `{ userId, planCode, scope }` or throws

JWT claims:
```json
{ "sub": "<userId>", "iss": "https://elementarmory.com",
  "aud": "https://mcp.elementarmory.com",
  "scope": "mcp:tools", "plan": "free", "exp": ..., "iat": ... }
```

### New route file: `server/src/api/routes/oauth.ts`

Mounted at root level (not under `/api`) so well-known paths work correctly.

| Endpoint | Purpose |
|---|---|
| `GET /.well-known/oauth-authorization-server` | RFC 8414 AS metadata |
| `POST /oauth/register` | Dynamic Client Registration (RFC 7591) |
| `GET /oauth/authorize` | Authorization endpoint (requires session; auto-approves `mcp:tools`) |
| `POST /oauth/token` | Token endpoint: `authorization_code` + `refresh_token` grant types |
| `POST /oauth/revoke` | Token revocation (optional, nice to have) |

**`GET /.well-known/oauth-authorization-server`** returns:
```json
{
  "issuer": "https://elementarmory.com",
  "authorization_endpoint": "https://elementarmory.com/oauth/authorize",
  "token_endpoint": "https://elementarmory.com/oauth/token",
  "registration_endpoint": "https://elementarmory.com/oauth/register",
  "response_types_supported": ["code"],
  "grant_types_supported": ["authorization_code", "refresh_token"],
  "token_endpoint_auth_methods_supported": ["none"],
  "code_challenge_methods_supported": ["S256"],
  "scopes_supported": ["mcp:tools"]
}
```

**`GET /oauth/authorize`**: If user not logged in → redirect to `/sign-in?return_to=/oauth/authorize?...`. If logged in → generate auth code, redirect to `redirect_uri?code=...&state=...`. Auto-approves `mcp:tools` with no consent screen needed (it's our own service).

**`POST /oauth/token`**: Validates grant type, PKCE verifier, returns:
```json
{ "access_token": "<JWT>", "token_type": "Bearer", "expires_in": 3600,
  "refresh_token": "<opaque>", "scope": "mcp:tools" }
```

### Remove:
- `server/src/api/routes/mcp-tokens.ts` — delete
- `server/src/services/mcp-token.ts` — delete
- `/internal/mcp/auth` endpoint from `server/src/api/routes/internal-mcp.ts` — remove this one handler (keep captures/usage routes)

### Mount in express:
`server/src/loaders/express.ts` — add `app.use('/', oauthRouter)` before existing routes.

## Step 3 — MCP Server: OAuth Protected Resource

### New env vars (`mcp-server/.env`):
- `JWT_SECRET` — same value as main server
- `MCP_SERVER_URL` — e.g. `https://mcp.elementarmory.com` (for audience validation)
- `MAIN_SERVER_URL` — unchanged (for usage increment calls)

### Changes to `mcp-server/src/index.ts`:

1. **Add `/.well-known/oauth-protected-resource` route** (no auth required):
```json
{
  "resource": "https://mcp.elementarmory.com",
  "authorization_servers": ["https://elementarmory.com"],
  "scopes_supported": ["mcp:tools"],
  "resource_name": "Element Armory MCP"
}
```

2. **On unauthenticated `/` requests** → return `401` with header:
```
WWW-Authenticate: Bearer realm="mcp", resource_metadata="https://mcp.elementarmory.com/.well-known/oauth-protected-resource"
```

3. **Replace API key extraction + `validateUserCode()`** with JWT validation:
   - Extract Bearer token from `Authorization` header only
   - Call `validateJwt(token)` → `{ userId, planCode, scope }`
   - No call to main server for auth (it's all in the JWT)
   - Pass user to tools as before

### Replace `mcp-server/src/auth.ts`:
New version validates HS256 JWT locally using `jsonwebtoken` (already a common dep or add it).

```typescript
import jwt from 'jsonwebtoken';

export function validateJwt(token: string): McpUser {
  const payload = jwt.verify(token, config.JWT_SECRET, {
    issuer: 'https://elementarmory.com',
    audience: config.MCP_SERVER_URL,
  }) as JwtPayload;
  return { userId: payload.sub, planCode: payload.plan, ... };
}
```

### Remove:
- API key pattern check (`API_KEY_PATTERN`)
- Custom header support (`element_armory_api_key`)
- `validateUserCode()` call to main server
- `mcp-server/src/cache.ts` — no longer needed (JWT validation is local)
